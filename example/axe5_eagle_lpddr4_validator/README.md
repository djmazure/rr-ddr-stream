# axe5_eagle_lpddr4_validator

Hardware test of `ddr_stream_axi` on the Arrow AXE5-Eagle board (Agilex 5
E-Series SoC, `A5ED065BB32AE4SR0`). The memory under test is the board's
fabric LPDDR4 device (1 GB).

## What the design does

| Block | Function |
|---|---|
| `ddr_validator_bist` | Writes a test pattern, reads it back, compares each word in the fabric. |
| `ddr_stream_axi` | IP under test. 256-bit AXI4 master, 512 MB ring buffer. |
| `emif_bank2a_fpga` | Fabric LPDDR4 controller (256-bit AXI4 slave). |
| `ddr_validator_csr` | AXI4-Lite register block. Linux starts a run and reads the result here. |
| `hps_subsys` | Agilex 5 HPS. Generated by rr from `ip.yml`. Gives the fabric clock, the `lwhps2fpga` bridge to the CSR block, and its own LPDDR4 for Linux. |

The test data never leaves the fabric. The HPS only reads and writes the CSR
block.

| Path | Content |
|---|---|

| `tcl/project_options.tcl` | Pin assignments; adds the fabric controller to the Quartus project. |

The three `.ip` files come from the board vendor's golden hardware reference
design for the AXE5-Eagle.

## Before the first build

The frozen HPS component also needs its generated synthesis tree,
`ip/agilex_hps/agilex_hps/`. rr does not generate it on its own: generated
standalone, the component loses its I/O pin-mux. Copy that directory from a
generated build of the board vendor's golden hardware reference design. rr
stops with `FROZEN HPS SYNTHESIS TREE IS MISSING` while it is absent.

If the host has more than one Quartus install, pin Quartus Prime Pro 26.1 for
this project. Make a target file (for example `targets/local.yml`, a copy of
`project.yml` with `hardware.tool_path` set) and select it with `--target`.

## Build

| Step | Command | Result |
|---|---|---|
| 1 | `rr queue submit synth` | rr generates `hps_subsys`, the hook generates the fabric controller, then Quartus synthesis. |
| 2 | `rr queue submit impl` | Fit and timing analysis. |
| 3 | `rr queue submit bitstream` | `.sof`. |
| 4 | `rr linux build` | SPL, U-Boot, kernel, device tree, ramdisk with `ddr_validator`, boot script. |
| 5 | `rr linux sof` | `.sof` with the HPS first-stage boot loader. |
| 6 | `rr linux flash-sd --device /dev/sdX` | SD card. Check the device name with `lsblk` first. |

Use `rr queue status` and `rr queue logs <job-id>` to follow steps 1 to 3.

`hps_fpga_bridges: all` in `project.yml` puts `bridge enable` in the boot
script. Without it, accesses to the CSR block fail.

## Run

1. Insert the SD card. Power the board.
2. Program the `.sof` from step 5: `rr program run --bitstream <file>`.
3. Wait for the Linux prompt on the console.
4. Run the tests:

| Command | Test |
|---|---|
| `ddr_validator` | Checks `IDENT`, then runs scenario 0. |
| `ddr_validator --scenario 0` | Roundtrip: write, read back, compare. |
| `ddr_validator --scenario 1 --n-words 524288` | Boundary: roundtrip over many bursts (16 MB). |
| `ddr_validator --scenario 2` | Reset recovery: the IP is reset once during the write pass, then the roundtrip completes. |

Scenario 3 (pingpong) is not implemented: it reports done, without pass or
fail.

Exit code 0 is pass, 1 is fail. A pass prints `DONE PASS` and `Errors 0`.

If `IDENT` does not read `0x0DD50200`: check that the `.sof` from step 5 was
programmed and that `bridge enable` ran in U-Boot (console log).

## LEDs

Active low. Bit 0 running, 1 done, 2 pass, 3 fail, 4 configuration not done,
5 to 7 heartbeat.

## Registers

Base address `0x20000000` (HPS lightweight HPS-to-FPGA bridge window).

| Offset | Name | Access | Reset | Content |
|---|---|---|---|---|
| 0x00 | IDENT | RO | 0x0DD50200 | Fixed signature |
| 0x04 | CONTROL | RW | 0x00000000 | bit 0 start, bit 1 soft reset |
| 0x08 | SCENARIO | RW | 0x00000000 | 0 roundtrip, 1 boundary, 2 reset recovery, 3 pingpong (not implemented) |
| 0x0C | N_WORDS | RW | 0x00010000 | Number of 256-bit words |
| 0x10 | STATUS | RO | 0x00000000 | bit 0 running, 1 done, 2 pass, 3 fail |
| 0x14 | ERROR_COUNT | RO | 0x00000000 | Mismatching words |
| 0x18 | WORDS_WR | RO | 0x00000000 | Words written |
| 0x1C | WORDS_RD | RO | 0x00000000 | Words read and compared |
| 0x20 | ERR_INDEX | RO | 0x00000000 | Index of the first mismatch |
| 0x24 | ERR_EXP_LO | RO | 0x00000000 | Expected data[31:0] at the first mismatch |
| 0x28 | ERR_GOT_LO | RO | 0x00000000 | Read data[31:0] at the first mismatch |
